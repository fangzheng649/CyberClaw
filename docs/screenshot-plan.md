## 二、分批执行计划

### 📷 Batch 0｜实拍照片（随时，独立做）

图4-2a / 4-2b / 4-2c —— 拿手机拍实验台。

- **4-2a**：俯拍全景，交换机居中，摄像头/NVR/ESP32 围绕摆放，光线充足
- **4-2b**：交换机正面特写，用后期标注 Port 1/2/3 接线（或拍照前贴临时标签）
- **4-2c**：摄像头正面特写，露出 PoE 网口

**ESP32（4-2d / 4-3）单独决策**：手头有开发板就拍+刷固件；没有就从报告弱化成"支持 MQTT 传感器接入（已验证协议层）"，删掉 4-2d/4-3 改为架构示意。**建议先跳过，不阻塞主流程。**

### 🎬 Batch 2｜跑一次 Mirai Demo 连环截（~5 分钟，拿下 4 图）

这是效率最高的一步。**一次 Demo 演示（90 秒）按阶段连拍**，一次拿下图4-6 / 图4-9 / 图4-14 共约 14 张子截图：

**准备**：录屏软件开着（OBS / Win+G 游戏栏 / ScreenToGif），Demo 跑起来后边播边按阶段暂停截图。

**图4-9 三段式**额外截：
- 隔离前在 Chat 触发一次手动隔离（输"隔离 cam_entrance"），截**确认卡片**（红色边框那张）
- 点确认后截**执行进度消息**（这块要补代码才有逐步消息，现版本只有一条"Isolating..."，可先截现有）
- 设备 attacked→isolated 状态变化截前后对比

**图4-6 五状态拼接**：把上面截到的 secure(初始)/scanning/vulnerable/attacked/isolated 五张设备特写横向拼，每张底下标状态名。

> 💡 **录屏兜底**：连拍容易漏，建议全程录屏，事后从视频逐帧截，最稳。

## 三、推荐执行顺序（最快推进文档）

```
第一步：实拍 4-2a/b/c（手机，10分钟，随时）
        ↓
第二步：开发 ReAct + 报告生成（阻塞图4-8/4-13）
        ↓
第三步：补 Batch 4 小修小补（隔离进度/评分条/振荡）
        ↓
第四步：启动系统 → Batch 1 静态界面 7 张（20分钟）
        ↓
第五步：跑 Mirai Demo 录屏 → Batch 2 连截 + Batch 3 两张 Chat（30分钟）
        ↓
第六步：拼接/标注（图4-6 五状态横拼、图4-14 六宫格、各合成图）
        ↓
ESP32（4-2d/4-3）：单独决策，不阻塞
```

**关键路径**：第二步（ReAct+报告开发）是瓶颈。开发完这两个，剩下截图加起来 1 小时内能全拿下。
