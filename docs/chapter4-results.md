# 第四章 运行结果与应用效果

本章从系统部署、实验平台搭建、核心功能运行效果、**端到端攻击链验证**和性能指标五个维度，全面展示CyberClaw系统的运行状态与应用效果。系统已完成全栈开发，并通过5种物理IoT设备与**19台仿真设备**的双重验证，覆盖**感知→检测→响应→复盘**四阶段闭环**的全部核心功能。

## 4.3 核心功能运行效果展示

本节按运维人员的实际使用流程，依次展示3D安全态势感知、AI智能分析、隔离响应、仪表盘管理、报告生成等核心功能的运行效果。

### 4.3.1 3D安全态势感知

**3D安全HUD**是CyberClaw面向运维人员的核心交互界面，在浏览器中渲染全网设备的三维拓扑视图，运维人员通过鼠标旋转、缩放、点击与设备交互。设备节点按类型映射为不同几何体形状——交换机为长方体、摄像头为圆锥体、服务器为高长方体、传感器为四面体等，节点颜色实时反映安全状态。设备间的网络连接通过三维空间中的连线渲染，连线颜色取源设备的当前状态色。

系统定义了**5种安全状态**及其对应的视觉效果：secure（绿色，设备正常运行，静态微弱呼吸效果）、scanning（蓝色，正在被扫描，触发波纹扩散动画——同心环从扫描源向目标设备扩散）、vulnerable（橙色，存在已知漏洞，触发振荡动画并增强发光）、attacked（红色，遭受攻击，触发全屏告警闪烁和**攻击光束**动画——红色弧形光束从攻击源连接至目标设备）、isolated（灰色，已隔离，叠加二十面体线框**防护盾**包裹）。安全事件触发**攻击光束**、扫描波纹、**防护盾**等动画特效，运维人员可直觉判断全网安全态势的变化。状态转换遵循"**不降级**"原则——已标记attacked（红色）的设备不会被后续低严重级别事件降级，确保高危状态的持续可见性。

点击设备节点后，右侧弹出设备详情面板，展示设备基础信息、开放端口列表（端口按风险等级着色——Telnet标红、RTSP标橙、SSH标绿）、CVE漏洞信息（含CVE编号、CVSS评分和漏洞描述）、合规评分进度条、连接设备列表和**安全事件时间线**等6个维度的安全数据，并提供了扫描、漏洞查询、隔离等快捷操作按钮。图4-5展示了**3D安全HUD**的全景视图和设备详情面板，图4-6展示了五种安全状态的视觉效果和攻防动画。

### 4.3.2 CyberAgent智能安全分析

**CyberAgent**是系统的AI安全分析中枢，运维人员通过自然语言对话驱动安全扫描和威胁分析。对话界面支持多会话管理，顶部提供"扫描网络""检查漏洞""安全基线""帮助"等快捷按钮，降低操作门槛。

图4-7展示了网络扫描的对话过程——运维人员输入"扫描网络"后，AI自动编排扫描工具执行网络发现和IoT指纹识别，实时展示分析步骤卡片（每张卡片显示工具名称、执行状态和结果摘要），扫描完成后返回设备发现结果，包括每台设备的IP地址、开放端口、设备类型和厂商信息。端口列表按风险等级着色——Telnet标红、RTSP标橙、HTTP标黄，运维人员可直觉判断端口风险。结果卡片同时提供"深入扫描"和"检查漏洞"两个快捷按钮，支持从扫描结果直接触发后续分析。

对于可疑设备，**CyberAgent**启动**多轮关联推理**，依次调用攻击时间线查询、端口扫描、CVE漏洞关联、**基线审计**、流量分析、IoC提取等多个安全工具构建完整证据链，并根据证据充分性动态调整推理深度——高风险设备执行全部**7轮深度分析**，低风险设备在3-4轮后快速输出结论。图4-8展示了推理过程的对话界面——以摄像头Camera-Entrance（IP 192.168.1.11）遭受Mirai感染为例，7张分析步骤卡片依次展开：读取攻击时间线（12次Telnet登录失败）→端口扫描（发现23/80/554端口开放）→CVE查询（发现CVE-2021-36260 CVSS 9.8等高危漏洞）→**基线审计**（合规评分62分，Telnet开放且使用默认密码）→流量分析（检测到150+IP的23/2323端口扫描行为）→IoC提取（发现C2回连185.220.101.34:443）→综合判定，最终输出结论："**Mirai僵尸网络**感染——置信度96%，建议立即隔离"。

### 4.3.3 隔离确认与自动响应

当AI分析结论建议执行**设备隔离**时，系统通过"**写操作须确认**"机制保障操作安全性——AI在Chat回复中生成隔离确认卡片，运维人员需主动点击确认按钮，系统不会自动执行隔离操作。

图4-9展示了隔离操作的全过程。确认卡片以醒目的红色边框样式呈现，包含目标设备信息（名称、IP地址、设备类型）、隔离原因（AI分析结论摘要，如"Mirai感染，置信度96%"）和拟执行操作详情，以及"确认隔离"和"取消"两个操作按钮。用户点击"确认隔离"后，系统依次执行**网络封禁**规则，Chat界面实时展示执行进度——"正在执行**网络封禁**...""正在连接交换机...""正在执行端口关闭 Port 1...""隔离验证通过，ping不可达"。隔离完成后，**3D安全HUD**中设备状态从红色（attacked）平滑过渡至灰色（isolated）并叠加**防护盾**动画，同时系统通过ntfy、WebSocket和Chat三个通道推送隔离确认通知。运维人员可在Chat中输入"恢复设备"触发逆向操作解除隔离。

## 4.4 Mirai僵尸网络端到端验证

### 4.4.1 攻击链全流程演示

为全面验证CyberClaw**四阶段安全闭环**在实际攻击场景下的协同工作能力，系统以**Mirai僵尸网络**攻击为案例执行**端到端攻击链验证**。**ScenarioService**按预设的**34步攻击脚本**驱动**10个攻击阶段**，24台设备参与验证，全程通过**3D安全HUD**和Chat界面实时展示攻击效果和系统响应。图4-14展示了攻击链6个关键阶段的3D HUD截图。

**阶段一：侦察与漏洞发现。** 系统从初始安全态势启动——24台设备全部处于绿色secure状态。外部攻击者从IP 10.0.1.1发起端口扫描，依次探测7台摄像头和NVR。3D场景中从攻击者节点向每台目标设备发射蓝色扫描波纹，被扫描设备依次从绿色过渡至蓝色scanning状态。随后CVE查询发现三组高危漏洞：CVE-2021-36260（CVSS 9.8，Hikvision命令注入）、CVE-2021-33044（CVSS 9.8，Dahua身份认证绕过）和默认密码，7台存在漏洞的设备从蓝色过渡至橙色vulnerable状态。

**阶段二：暴力破解与首次感染。** 攻击者利用默认凭据通过Telnet暴力破解入口摄像头。3D场景中触发红色**攻击光束**——弧形路径从攻击者连接至目标设备，同时激活全屏告警闪烁。摄像头从橙色过渡至红色attacked状态，触发脉冲缩放动画。系统触发全通道告警推送。

**阶段三：**横向扩散**与C2检测。** Mirai蠕虫从已感染设备向网络中其他设备扩散，7步横向移动依次触发橙色**攻击光束**连接源设备和目标设备，6台受感染设备逐一变红。流量分析检测到大量不同目的IP与固定端口23/2323的扫描行为，识别Mirai扩散特征。随后IoC提取发现受感染设备向外部IP 185.220.101.34:443发送**C2心跳回连**，3D场景中渲染紫色外泄光束。

**阶段四：AI综合分析。** **CyberAgent**完成**多轮关联推理**，串联attack-timeline、nmap-scan、cve-intel、security-baseline、flow-analyzer和traffic-analyzer六个MCP工具。Chat界面展示分析步骤卡片和最终结论："**Mirai僵尸网络**感染——6台设备受控（含NVR），置信度96%，建议立即隔离"。

**阶段五：自动隔离响应。** 系统依次隔离6台受感染设备。每步触发**防护盾**动画——设备整体缩小并叠加线框护盾（弹性缩放动画），状态从红色平滑过渡至灰色isolated。

**阶段六：威胁清除与复盘。** **CyberAgent**自动生成Mirai攻击时间线报告，包含攻击链还原、根因分析（入口为**默认密码暴力破解**）和改进建议（全网禁用默认密码、关闭Telnet、部署CVE补丁）。

> **【图4-14】Mirai攻击链端到端验证关键阶段** — 六宫格布局展示6个关键瞬间的3D HUD截图：①初始态势（全部绿色secure）；②侦察扫描（7台摄像头变蓝色scanning，蓝色波纹扩散中）；③首次感染（入口摄像头变红色attacked，红色攻击光束+全屏告警闪烁）；④横向扩散（6台设备变红色，攻击光束交错）；⑤自动隔离（6台设备变灰色isolated，防护盾包裹）；⑥威胁清除（全部受感染设备完成隔离）。每张下方标注阶段名称。

本章从系统部署、实验环境、核心功能、端到端验证和性能指标五个维度展示了CyberClaw系统的运行结果与应用效果。在实验平台方面，系统成功接入TP-LINK可管理PoE交换机、海康威视网络摄像头、NVR录像机和ESP32+DHT22传感器等5种真实IoT设备，覆盖网络基础设施、视频监控终端和工业传感终端三类设备角色，并通过**19台仿真设备**扩展至24台的混合验证环境。
