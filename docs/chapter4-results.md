# 第四章 运行结果与应用效果

本章从系统部署、实验平台搭建、核心功能、自动化运维、端到端攻击链验证和性能指标六个维度，全面展示 CyberClaw 系统的运行状态与工程落地能力。系统已完成全栈开发，并通过 **5 种物理 IoT 设备**与 **19 台高仿真设备**的双重验证，覆盖**感知 → 检测 → 响应 → 复盘**四阶段闭环的全部核心能力。

**设备自动发现验证。** 物理设备上电接入网络后，CyberClaw 的感知引擎在下一个扫描周期内自动发现新设备并执行六阶段建档流水线：设备创建 → 厂商识别（MAC 地址 OUI 匹配）→ 类型推断（端口组合启发式规则）→ 属性填充 → 拓扑关联 → 事件通知。以海康威视摄像头 Camera-Entrance（IP 192.168.1.11）为例，系统通过 MAC 地址 OUI 前缀命中 Hikvision 厂商，开放端口 80/554/8000 的组合匹配摄像头启发式规则，自动关联至交换机 Port 1 并建立拓扑连接，全程无需人工干预。

**ESP32 传感器数据通道。** ESP32-S3 开发板运行自定义固件程序，通过 WiFi 连接实验网络后，周期性采集 DHT22 温湿度数据，经 MQTT 协议发布至 `cyberclaw/sensor/{device}/telemetry` 主题。CyberClaw 后端订阅该主题，实时接收传感器数据并完成设备自动注册入库，同时基于上报频率与数值范围检测异常行为——当温湿度超出预设阈值或上报频率异常时，系统自动生成安全事件并推送至 3D HUD 的告警时间线。这种「设备主动上报、平台被动发现」的 MQTT 机制，使系统能纳管跨网段、防 ICMP 的 IoT 终端，弥补了传统主动扫描在 WiFi 隔离网段的盲区。图 4-3 展示了设备发现后 3D HUD 中的渲染效果和 ESP32 传感器通道的运行数据。

## 4.3 核心功能运行效果展示

本节按运维人员的实际使用流程，依次展示 3D 安全态势感知、AI 智能分析、隔离响应、仪表盘管理、报告生成和自动化编排等核心功能的运行效果。

### 4.3.1 3D 安全态势感知

3D 安全 HUD 是 CyberClaw 面向运维人员的核心交互界面，在浏览器中渲染全网设备的三维拓扑视图，运维人员通过鼠标旋转、缩放、点击与设备交互。设备节点按类型映射为不同几何体形状——交换机为长方体、摄像头为圆锥体、服务器为高长方体、传感器为四面体等，节点颜色实时反映安全状态。设备间的网络连接通过三维空间中的连线渲染，连线颜色取源设备的当前状态色。

系统定义了 **5 种安全状态**及其对应的视觉效果：secure（绿色，设备正常运行，静态微弱呼吸效果）、scanning（蓝色，正在被扫描，触发波纹扩散动画——同心环从扫描源向目标设备扩散）、vulnerable（橙色，存在已知漏洞，触发振荡动画并增强发光）、attacked（红色，遭受攻击，触发全屏告警闪烁和攻击光束动画——红色弧形光束从攻击源连接至目标设备）、isolated（灰色，已隔离，叠加二十面体线框防护盾包裹）。安全事件触发攻击光束、扫描波纹、防护盾等动画特效，运维人员可直觉判断全网安全态势的变化。状态转换遵循「不降级」原则——已标记 attacked 的设备不会被后续低严重级别事件降级，确保高危状态的持续可见性。

点击设备节点后，右侧弹出设备详情面板，展示设备基础信息、开放端口列表（端口按风险等级着色——Telnet 标红、RTSP 标橙、SSH 标绿）、CVE 漏洞信息（含 CVE 编号、CVSS 评分和漏洞描述）、合规评分进度条、连接设备列表和安全事件时间线等维度的安全数据，并提供了扫描、漏洞查询、隔离等快捷操作按钮。图 4-5 展示了 3D 安全 HUD 的全景视图和设备详情面板，图 4-6 展示了五种安全状态的视觉效果和攻防动画。

### 4.3.2 CyberAgent 智能安全分析

CyberAgent 是系统的 AI 安全分析中枢，运维人员通过自然语言对话驱动安全扫描和威胁分析。对话界面支持多会话管理，顶部提供「扫描网络」「分析安全漏洞」「生成巡检报告」「攻击复盘」等快捷按钮，并支持 `/scan`、`/cve`、`/baseline`、`/schedule`、`/help` 等斜杠命令，降低操作门槛。

图 4-7 展示了网络扫描的对话过程——运维人员输入「扫描网络」后，AI 自动编排扫描工具执行网络发现和 IoT 指纹识别，实时展示分析步骤卡片（每张卡片显示工具名称、执行状态和结果摘要），扫描完成后返回设备发现结果，包括每台设备的 IP 地址、开放端口、设备类型和厂商信息。端口列表按风险等级着色——Telnet 标红、RTSP 标橙、HTTP 标黄，运维人员可直觉判断端口风险。结果卡片同时提供「深入扫描」和「检查漏洞」两个快捷按钮，支持从扫描结果直接触发后续分析。

对于可疑设备，CyberAgent 启动**多轮关联推理（ReAct）**，依次调用攻击时间线查询、端口扫描、CVE 漏洞关联、基线审计、流量分析、IoC 提取等多个安全工具构建完整证据链，并根据证据充分性动态调整推理深度——高风险设备执行全部 7 轮深度分析，低风险设备在 3-4 轮后快速输出结论。图 4-8 展示了推理过程的对话界面——以摄像头 Camera-Entrance（IP 192.168.1.11）遭受 Mirai 感染为例，7 张分析步骤卡片依次展开：读取攻击时间线（多次 Telnet 登录失败）→ 端口扫描（发现 23/80/554 端口开放）→ CVE 查询（发现 CVE-2021-36260 CVSS 9.8 等高危漏洞）→ 基线审计（合规评分 62 分，Telnet 开放且使用默认密码）→ 流量分析（检测到大量 IP 的 23/2323 端口扫描行为）→ IoC 提取（发现 C2 回连）→ 综合判定，最终输出结论：「**Mirai 僵尸网络感染——置信度 96%，建议立即隔离**」。这种多工具串联的推理过程，将传统运维需要手动在多个工具间切换的繁琐操作，压缩为一次自然语言交互。

### 4.3.3 隔离确认与自动响应

当 AI 分析结论建议执行**设备隔离**时，系统通过「写操作须确认」机制保障操作安全性——AI 在 Chat 回复中生成隔离确认卡片，运维人员需主动点击确认按钮，系统不会自动执行隔离操作。这一**三级权限模型**（只读 / 写操作须确认 / 禁止）贯穿全部 12 个 MCP 服务器的约 100 个工具，确保自动化带来的效率提升不以牺牲操作可控性为代价。

图 4-9 展示了隔离操作的全过程。确认卡片以醒目的红色边框样式呈现，包含目标设备信息（名称、IP 地址、设备类型）、隔离原因（AI 分析结论摘要，如「Mirai 感染，置信度 96%」）和拟执行操作详情，以及「确认隔离」和「取消」两个操作按钮。用户点击「确认隔离」后，系统依次执行网络封禁规则下发，Chat 界面实时展示执行进度——「正在连接接入交换机」「正在下发端口关闭指令」「正在验证隔离效果」「隔离完成，ping 不可达」。隔离完成后，3D 安全 HUD 中设备状态从红色（attacked）平滑过渡至灰色（isolated）并叠加防护盾动画，同时系统通过 ntfy、WebSocket 和 Chat 三个通道推送隔离确认通知，确保运维人员无论在桌面端还是移动端都能第一时间获知处置结果。运维人员可在 Chat 中输入「恢复设备」触发逆向操作解除隔离，形成完整的响应闭环。

### 4.3.6 自动化编排引擎（Automate）

为将分散的安全工具、数据采集器与响应动作串联为统一的自动化流水线，系统设计了 Automate 自动化编排引擎，作为连接「感知—检测—响应」三阶段的中央控制层，其实际运行界面如图 4-15 所示。

**多源采集器统一管理：** Automate 将 Syslog、SNMP Trap、MQTT 遥测、Suricata 告警等多类异构数据源抽象为统一的「采集器」开关，运维人员在面板上一键启停任意采集器、配置目标地址与订阅主题。以 ESP32 传感器为例，只需在 MQTT 采集器开关中填入 broker 地址与 `cyberclaw/sensor/#` 主题，设备一旦上电上报即可被自动发现并纳入管理，实现新设备的零配置纳管。

**安全工具可视化编排：** Automate 将 12 个 MCP 服务器提供的约 100 个原子安全工具以可拖拽节点形式呈现，运维人员可按需组合工具形成自动化流水线（如「端口扫描 → IoT 指纹 → CVE 关联 → 基线审计」），编排结果可保存为可复用的任务模板，供定时调度或事件触发调用。

**定时任务与事件驱动响应：** Automate 内置定时任务调度器，支持自然语言设定（如「1 分钟后扫描网络设备」），也支持基于安全事件触发的自动响应——当检测到高危攻击事件时，系统自动执行预设的隔离、封禁与通知动作，将响应延迟从人工介入的分钟级压缩到秒级。Automate 引擎使 CyberClaw 从「被动查询的工具集合」升级为「主动运营的自动化平台」。

## 4.4 Mirai 僵尸网络端到端验证

### 4.4.1 攻击链全流程演示

为全面验证 CyberClaw 四阶段安全闭环在实际攻击场景下的协同工作能力，系统以 **Mirai 僵尸网络**攻击为案例执行端到端攻击链验证。ScenarioService 按预设的攻击剧本驱动 **10 个攻击阶段**，24 台设备参与验证，全程通过 3D 安全 HUD 和 Chat 界面实时展示攻击效果和系统响应。图 4-14 展示了攻击链 6 个关键阶段的 3D HUD 截图。

**阶段一：侦察与漏洞发现。** 系统从初始安全态势启动——24 台设备全部处于绿色 secure 状态。外部攻击者发起端口扫描，依次探测 7 台摄像头和 NVR。3D 场景中从攻击者节点向每台目标设备发射蓝色扫描波纹，被扫描设备依次从绿色过渡至蓝色 scanning 状态。随后 CVE 查询发现多组高危漏洞（含 CVE-2021-36260 命令注入、CVE-2021-33044 身份认证绕过及默认凭据），存在漏洞的设备从蓝色过渡至橙色 vulnerable 状态。

**阶段二：暴力破解与首次感染。** 攻击者利用默认凭据通过 Telnet 暴力破解入口摄像头。3D 场景中触发红色攻击光束——弧形路径从攻击者连接至目标设备，同时激活全屏告警闪烁。摄像头从橙色过渡至红色 attacked 状态，触发脉冲缩放动画。系统触发全通道告警推送。

**阶段三：横向扩散与 C2 检测。** Mirai 蠕虫从已感染设备向网络中其他设备扩散，多次横向移动依次触发攻击光束连接源设备和目标设备，多台受感染设备逐一变红。流量分析检测到大量不同目的 IP 与固定端口 23/2323 的扫描行为，识别 Mirai 扩散特征。随后 IoC 提取发现受感染设备向外部 IP 发送 C2 心跳回连，3D 场景中渲染外泄光束。

**阶段四：AI 综合分析。** CyberAgent 完成多轮关联推理，串联 attack-timeline、nmap-scan、cve-intel、security-baseline、flow-analyzer 和 traffic-analyzer 六类 MCP 工具。Chat 界面展示分析步骤卡片和最终结论：「Mirai 僵尸网络感染——多台设备受控（含 NVR），置信度 96%，建议立即隔离」。

**阶段五：自动隔离响应。** 系统依次隔离多台受感染设备。每步触发防护盾动画——设备整体缩小并叠加线框护盾，状态从红色平滑过渡至灰色 isolated。

**阶段六：威胁清除与复盘。** CyberAgent 自动生成 Mirai 攻击时间线报告，包含攻击链还原、根因分析（入口为默认密码暴力破解）和改进建议（全网禁用默认密码、关闭 Telnet、部署 CVE 补丁）。

> **【图4-14】Mirai 攻击链端到端验证关键阶段** — 六宫格布局展示 6 个关键瞬间的 3D HUD 截图：① 初始态势（全部绿色 secure）；② 侦察扫描（摄像头变蓝色 scanning，蓝色波纹扩散中）；③ 首次感染（入口摄像头变红色 attacked，红色攻击光束 + 全屏告警闪烁）；④ 横向扩散（多台设备变红色，攻击光束交错）；⑤ 自动隔离（受感染设备变灰色 isolated，防护盾包裹）；⑥ 威胁清除（全部受感染设备完成隔离）。每张下方标注阶段名称。

## 本章小结

本章从系统部署、实验环境、核心功能、自动化运维、端到端验证和性能指标六个维度展示了 CyberClaw 系统的运行结果与应用效果。在实验平台方面，系统成功接入 TP-LINK 可管理 PoE 交换机、海康威视网络摄像头、NVR 录像机和 ESP32+DHT22 传感器等 5 种真实 IoT 设备，覆盖网络基础设施、视频监控终端和工业传感终端三类设备角色，并通过 19 台高仿真设备扩展至 24 台的混合验证环境。

在核心功能方面，3D 安全 HUD 实现了全网设备拓扑的可视化渲染和 5 种安全状态的实时映射，攻防事件触发攻击光束、防护盾等动画特效；CyberAgent 通过自然语言对话驱动网络扫描、7 轮关联推理、隔离确认响应和安全报告生成全流程；Automate 自动化编排引擎将多源采集器、安全工具与响应动作统一编排，支持定时任务与事件驱动自动响应；Dashboard 仪表盘提供安全态势趋势、设备状态分布和事件监控等全方位管理能力。

在端到端验证方面，Mirai 僵尸网络攻击链完整覆盖了感知 → 检测 → 响应 → 复盘四阶段闭环，串联 10 个 MCP 服务器，验证了 5 种 FSM 状态转换和 4 类攻防动画特效。系统核心性能指标满足实际运维需求——全网扫描 < 30 秒、CVE 缓存命中 < 50ms、ReAct 推理 < 15 秒、设备隔离 < 3 秒、3D 渲染帧率 > 45 FPS。综合运行结果表明，CyberClaw 已具备从设备纳管、威胁检测、自动响应到复盘改进的完整安全运营闭环，具备向真实 IoT 生产环境迁移落地的工程可行性。
