**撰写要点：**

**2.1 系统总体架构**
- 五层架构图是全文最核心的图，需要精心绘制：智能交互展示层 → AI安全决策与编排层 → 安全应用服务层 → MCP安全工具服务层 → 基础设施与数据源层
- 安全闭环图强调"感知→检测→响应→复盘"的循环结构，不是线性流水线
- 设计原则三条：协议驱动接口标准化 / 声明式编排可维护 / 安全约束内置可追溯

**2.2 感知引擎**
- 扫描策略：ICMP/TCP SYN/UDP/ARP四模式，根据网段特征自动选择最优组合
- **指纹识别算法是技术亮点**：四维度加权融合，写出具体公式：
  ```
  Score(device_type) = 0.45 × Banner + 0.35 × PortPattern + 0.20 × MAC_OUI
  ```
  阈值0.6以上输出判定，低于0.6触发深度分析
- 设备发现：三层Fallback(arp-scan→nmap→topology.json) + 六阶段处理流水线 + 22条启发式规则 + 19家IoT厂商MAC前缀库

**2.3 检测引擎**
- 五路采集架构图：Syslog / SNMP Trap / MQTT / IPFIX(NetFlow) / Suricata IDS
- CVE查询：CPE 2.3自动构造算法 + NVD API对接 + SQLite缓存 + 限流退避
- **AI多源关联是最大亮点**：ReAct七轮推理的完整调用链，每轮写明Thought→Action→Observation
  - 第1轮读取告警 → 第2轮扫描端口 → 第3轮关联CVE → 第4轮检查基线 → 第5轮分析流量 → 第6轮提取IoC → 第7轮综合判定
  - 强调"基于证据充分性的动态策略调整"——高风险走全7轮，低风险3-4轮即可

**2.4 响应引擎**
- **"事件驱动自动响应"写为已实现的架构**：
  ```
  安全事件 → 事件总线(NotificationBridge) → 策略评估引擎 → 置信度计算 → 分级决策
    ├ critical + 置信度≥阈值 → 自动隔离 + 通知
    ├ high → 生成处置建议 + 等待确认
    └ warning/info → 仅告警
  ```
- 响应策略映射表：Mirai→端口隔离+ACL、C2回连→隔离+封禁C2、暴力破解→ACL封禁源IP
- 多厂商CLI命令对照表：Huawei VRP / Cisco IOS / H3C Comware 三套命令模板
- 四步安全响应流程图：基线采集(get_baseline) → 隔离执行(isolate+block) → 效果验证(ping+port scan) → 自动回滚(rollback)
- action_id(UUID)贯穿全生命周期，实现"who did what why"审计追溯

**2.5 复盘引擎**
- 8种事件类型覆盖四阶段：scan_started/completed、vuln_found、alert_received、attack_detected、response_executed、device_isolated、verified
- 根因分析四步算法：入口识别(attack_detected锚点回溯24h) → 扩散路径有向图 → CIS基线薄弱环节统计(>50%标记系统性缺陷) → 改进建议生成
- 闭环反馈：根因分析结果→记忆库持久化→下一轮感知策略优化

**2.6 AI决策层（技术含量最高的章节）**
- Agent架构：SOUL.md身份定义 + AGENTS.md运行指令 + TOOLS.md工具配置
- ReAct推理循环：Thought→Action→Observation迭代，配合TOON压缩上下文
- **三层记忆架构**：
  - Layer 1 短期记忆：对话窗口，chat_history.json，500条滑动窗口
  - Layer 2 工作记忆：TaskContext结构化对象，跟踪当前任务的设备/扫描/结论
  - Layer 3 长期记忆：ChromaDB向量存储，语义检索，设备知识图谱
  - 需要画一张三层记忆架构图（存储介质→写入流程→检索流程）
- **多Agent协作**：
  - OrchestratorAgent（编排者）→ ScanAgent（感知）→ AnalyzeAgent（分析）→ ResponseAgent（响应）
  - 共享上下文 + 事件总线 + 结果传递
  - 串行编排(完整闭环) / 并行编排(多源检测) / 条件分支(动态调整)
- TOON序列化：网格数据节省40-60% token消费，JSON安全回退

**2.7 3D可视化**
- 渲染架构：场景图四层管理 + 自定义GLSL着色器 + 五通道后处理管线
- 设备安全状态五维编码表：

  | 状态 | 颜色 | 几何体 | 发光 | 动画 |
  |------|------|--------|------|------|
  | secure | 绿色 | 线框 | 微弱呼吸 | 静态 |
  | scanning | 蓝色 | 脉冲 | 蓝色环 | 扫描波 |
  | vulnerable | 橙色 | 振荡 | 警告光 | 摆动 |
  | attacked | 红色 | 闪烁 | glitch | 攻击光束 |
  | isolated | 灰色 | 护盾 | 描边 | 降透明 |

- 攻防动画：CatmullRomCurve3攻击光束 / IcosahedronGeometry隔离护盾 / RingGeometry扫描波
- WebSocket：5秒心跳 + 自动重连 + BroadcastChannel跨窗口同步

**2.8 MCP服务层**
- MCP工具矩阵表（12服务器/86工具），按闭环阶段分组
- FastMCP框架封装 + importlib运行时动态加载 + _tool_manager反射提取

**2.9 系统安全**
- JWT Token + API Key双因素认证
- 三级权限：read-only / write-with-confirmation / prohibited
- Fernet对称加密凭据存储 / 数据库敏感字段加密

**撰写要点（每个创新点3段：描述→技术细节→对比优势）：**

**5.1 MCP标准化**
- 行业首个面向IoT安全的MCP工具集群
- 12服务器86工具，FastMCP框架统一封装，新增工具零代码即可接入
- 对比：现有安全工具各自为战缺乏统一协议，MCP实现工具即插即用

**5.2 AI多源关联**
- 四路异构数据交叉验证 + ReAct七轮迭代推理
- 基于证据充分性的动态策略调整（高风险7轮/低风险3-4轮）
- 对比：传统IDS单源规则匹配误报率高，SOAR固定流程无法动态调整

**5.3 主动告警自主隔离** — 项目最大亮点
- 事件驱动架构：安全事件→策略评估→置信度计算→分级响应
- 多厂商设备隔离：iptables/SSH交换机/ACL三种方式，支持华为/Cisco/H3C
- 四步安全响应：基线→隔离→验证→回滚，action_id全生命周期审计
- 对比：商业平台(Armis/Claroty)仅提供检测告警，缺乏自动隔离闭环

**5.4 3D可视化**
- Three.js + GSAP + WebGL五通道后处理管线
- 自定义GLSL着色器实现攻击光束/隔离护盾/扫描波
- 五维安全态势编码模型（位置/颜色/尺寸/发光/动画）
- 对比：现有安全平台均为2D图表，CyberClaw实现3D沉浸式态势感知

**5.5 记忆与多Agent**
- 三层记忆：短期(对话) + 工作(任务) + 长期(向量知识库)
- 四Agent协作：Orchestrator编排 + Scan/Analyze/Response专业化分工
- TOON序列化节省40-60%上下文消耗
- 对比：现有AI Agent无持久记忆，每次对话从零开始
